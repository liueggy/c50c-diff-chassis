# JDY-33无线控制与客户端开发（接口v1.2）

本车使用JDY-33，经C50C的UART4（PC10 TX、PC11 RX）透传控制数据。固件默认UART4为9600、8N1，宏 `CHASSIS_BLUETOOTH_BAUD` 可改；实际模块串口速率必须与之匹配，编译固件不会自动修改模块配置。ROS继续经USART3（115200），两种连接使用同一速度帧，但各有独立接收缓冲、帧解析和超时状态。

## 1. 软件与网页的连接选择

- 电脑蓝牙配对若产生SPP虚拟串口：原生软件直接打开该端口；现有Python网页服务也可使用该端口。浏览器访问本机网页，由Python进程负责蓝牙串口。
- Android等原生应用可选择设备支持的SPP/RFCOMM或BLE透传，由应用把下述原始字节写入连接。
- 浏览器直接连蓝牙须走Web Bluetooth/BLE，并非SPP。需要支持相应API的浏览器、HTTPS或localhost安全上下文，以及用户手势选设备；不保证所有手机/浏览器都支持。

JDY厂商手册中的默认BLE服务为FFE0，特征为FFE1/FFE2；不同固件、修改过的UUID和属性可能不同。应用应发现实际GATT服务，核对可写与通知属性后选择通道，不能只凭模块型号断定某一特征可写。蓝牙一次通知可能只含半帧，或连着多帧；接收器必须按字节流解析。

本次没有对实物发送AT设置命令，也未实测SPP配对或BLE特征。首次连接可先确认广播名/版本与实际串口速率；如需修改AT配置，请在电机失能、断开运动客户端的维护条件下按手册操作。旧APP的字母方向、调参、翻页、复位和无线烧录指令在Chassis构建中不再解析，避免误改PI或复位。旧车型保留原行为。

## 2. 控制权规则

1. 上电约12.3秒且物理条件允许后，发送零速度帧。无人控制时，首先成功解析零帧的端口成为控制方；同一控制周期两端同时申请时UART3优先。
2. 当前控制方持续发送指令即可一直控制，无固定测试时长。建议20 Hz；每两帧之间必须小于500ms。无线有效距离和质量取决于现场，不是无限距离。
3. 另一端口的运动、零帧、坏帧和释放请求均不影响当前控制方，也不会刷新其超时。蓝牙和ROS不能叠加速度或抢占。
4. 零速度表示停止但保留控制权。需要交接时由当前控制方发释放帧并停止发送所有心跳；也可关闭其发送进程/串口，等待500ms超时。
5. 当前控制方超时、坏帧或物理失能时，清PWM/PI并撤销控制权；两路排队数据被丢弃，恢复后必须新的零帧再申请，禁止自动使用另一端口的旧速度。
6. 控制权仲裁不是身份认证。只与可信设备配对；模块配对和应用访问权限由部署方配置。

模块STAT引脚没有接入本次控制逻辑。断连依靠接收指令超时检测，计时从最后一帧到达STM32开始；无线链路/操作系统缓冲延迟需要现场测量。应用断连/重连时必须清空旧待发速度，不排队重放。

## 3. 发送帧（11字节）

| 字节 | 内容 |
|---|---|
| 0 | 7B |
| 1 | 00速度；10释放控制（十六进制） |
| 2 | 00保留 |
| 3–4 | vx，有符号16位大端，mm/s，范围−700～700 |
| 5–6 | vy，必须00 00 |
| 7–8 | wz，有符号16位大端，mrad/s，范围−1000～1000 |
| 9 | 字节0～8逐字节XOR |
| 10 | 7D |

释放帧要求vx/vy/wz全部为0。发送的是二进制字节，不是字符串“7B 00 …”，也不是JSON。正vx前进，负vx后退；正wz逆时针左转，负wz右转。直行、后退、原地转向和曲线运动均用vx/wz组合，无需另设方向字母。

| 用途 | 完整十六进制帧 |
|---|---|
| 零速度/申请控制 | `7B 00 00 00 00 00 00 00 00 7B 7D` |
| 前进80 mm/s | `7B 00 00 00 50 00 00 00 00 2B 7D` |
| 后退80 mm/s | `7B 00 00 FF B0 00 00 00 00 34 7D` |
| 左转0.5 rad/s | `7B 00 00 00 00 00 00 01 F4 8E 7D` |
| 右转0.5 rad/s | `7B 00 00 00 00 00 00 FE 0C 89 7D` |
| 释放控制 | `7B 10 00 00 00 00 00 00 00 6B 7D` |

零帧与异常均当周期清输出，不经过普通平滑减速；实车机械停止时间仍与惯性和负载有关。完整电压/使能和错误语义见[串口控制说明](串口控制说明.md)。

## 4. 接收两类帧

原22字节状态帧保持不变：`5A status 左轮 右轮 电压 加速度XYZ 角速度XYZ XOR A5`，字段和单位见主协议。新增独立6字节控制权帧，两者约20 Hz广播到UART1、UART3和蓝牙UART4：

| 字节 | 内容 |
|---|---|
| 0 | 5B |
| 1 | 01：控制权帧版本 |
| 2 | owner：00无人、03 UART3/ROS、04 UART4/蓝牙 |
| 3 | 状态：00等零帧、01已解锁、02超时、03物理失能、04接收错误 |
| 4 | 前4字节XOR |
| 5 | A6 |

例如蓝牙已控制：`5B 01 04 01 5F A6`。状态帧bit0=ARMED，bit4=输出停止；二者同时为1是正常零速待命。蓝牙应用确认owner=4且ARMED、EN有效、无错误后才显示“可控制”，不能看到ARMED就认为自己取得了控制权。

接收流程：按5A取22字节、按5B取6字节；长度未满先等待，校验/帧尾不符丢1字节重新找头。不要把一次BLE通知或串口read当成一帧。控制权帧和遥测都超过0.5秒未更新时，界面应禁止运动并清除旧指令。

UART4使用28字节整组TXE中断发送，不在控制任务里阻塞等待9600波特率发完；忙时丢弃整组旧周期，不发送半组。额外的旧APP日志/数据显示已关闭，避免污染二进制流。

## 5. 自研客户端的最小状态机

`断开 → 连接 → 周期零帧 → owner为本通道 → 可运动 → 松开/失焦发零 → 释放/断开`

- 20 Hz发送最新速度；软件侧也设操作/上游消息超时，例如300～500ms。不能为保活而永远重复已失效的非零速度。
- 页面/窗口失焦、按钮松开、输入异常，立即请求零速度；设备失能、收到错误、回传过期后，清缓存并要求新的用户操作。
- 切换控制方：原端先释放并停止心跳，新端再周期零帧；收到owner确认后才发非零。
- 程序退出可发零速度和释放帧；释放帧之后不要再发零心跳，否则会重新申请控制。
- BLE写入可能异步：同一时间只保留最新待发指令，控制发送频率，不堆积历史速度。

JavaScript打包示例（与具体蓝牙API分离）：

```javascript
function frame(vx, wz, release = false) {
  if (![vx, wz].every(Number.isFinite) || Math.abs(vx) > 700 || Math.abs(wz) > 1000)
    throw new RangeError('invalid speed');
  if (release && (vx !== 0 || wz !== 0)) throw new RangeError('release must be zero');
  const bytes = new Uint8Array(11), view = new DataView(bytes.buffer);
  bytes[0] = 0x7b; bytes[1] = release ? 0x10 : 0;
  view.setInt16(3, Math.round(vx), false);
  view.setInt16(7, Math.round(wz), false);
  for (let i = 0; i < 9; ++i) bytes[9] ^= bytes[i];
  bytes[10] = 0x7d;
  return bytes;
}
```

输入是mm/s与mrad/s；ROS的m/s、rad/s需先乘1000。纯JS示例只负责编码，不会自行连接或驱动车辆。

## 6. 现有参考工具

```powershell
# COM7只是示例：必须是配对后的JDY-33虚拟串口
python tools/chassis_web.py --source bluetooth --port COM7
python tools/serial_drive.py --source bluetooth --port COM7 --vx 80 --duration 2
python tools/serial_drive.py --source bluetooth --port COM7 --release
```

手机（安卓）可用 [tools/bluetooth_control.html](../tools/bluetooth_control.html)：**Web Bluetooth 直连 JDY-33、无需电脑**（浅色页面，摇杆/方向键/键盘，按住走、松开停）。把它托管到 HTTPS（如 GitHub Pages）后，用 **Android Chrome** 打开即可控制；**iOS 不支持 Web Bluetooth**。

网页仍在 `http://127.0.0.1:8000/`，按住运行/松开停机；仅关闭浏览器页面不释放后台进程的控制权，交接时应退出网页服务并等待超时。CLI释放也不能与另一个占用同一COM口的进程并行打开；自研应用可在已有连接里直接发释放帧。CLI不解析控制权回传，推荐以网页的owner显示或自行解析确认。

SPP/BLE调试应先架空驱动轮。需要pyserial；不会安装ROS节点或修改上位机工程。

## 7. 验证与待实测

主机测试覆盖双通道隔离、同时申请、非控制方干扰、释放交接、超时不接续旧数据、物理恢复重解锁、UART4硬件错误与TXE整帧发送、网页混流/owner匹配/过期。固件编译通过不等于无线链路已实测。

待实测：JDY实际波特率、SPP配对/BLE GATT属性、遥测收发、前后左右运动、蓝牙断连停机、ROS与蓝牙交接。无线传输距离和最坏停止延迟以现场记录为准。
