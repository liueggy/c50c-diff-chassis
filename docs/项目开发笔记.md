# 项目开发笔记（面向开发者的速查）

> 目标读者：接手本仓库的开发者。只讲整体逻辑、接口约定和接线规则，细节看代码与链接的其他文档。
> 主线 issue：[#2 接入 BTS7960 电机驱动模块](https://github.com/liueggy/c50c-diff-chassis/issues/2)

## 1. 项目是什么

WHEELTEC C50C 底盘固件的二次开发工程：

- **平台**：STM32F407VE + FreeRTOS，Keil MDK5 + ARM Compiler 5（**不是 CMake**）
- **车型**：主开发线为 `Diff_Car`（两轮差速），由 `CarType/Inc/chassis_config.h` 的 `CHASSIS_ENABLED` 门控；其余 target（Akm/Mec/4WD/Omni）是保留的原厂基线
- **本开发线的特殊任务**：底盘之外，驱动一个**升降平台直流电机**（单电机、单 BTS7960 模块，非车轮）
- **控制方式**：ROS 串口（USART3 115200）与 JDY-33 蓝牙（UART4 9600）双通道，网页/手机蓝牙可直控

## 3. 硬件接线规则（升降平台）

**电源**：板上 12V 电池；`CHASSIS_STOP_VOLTAGE_V = 9.5V` 以下禁止一切输出（含升降）。

### 3.1 BTS7960（IBT-2 模块）→ 排针（实测丝印）

| 模块信号 | 排针 | MCU 引脚 | 说明 |
|---|---|---|---|
| RPWM | D8 | PD8 | 高=升 |
| LPWM | D9 | PD9 | 高=降 |
| R_EN + L_EN（短接） | 5V | — | 常使能 |
| VCC / GND | 5V / GND | — | 74HC244 逻辑电源，与模块 GND、电池共地 |
| R_IS / L_IS | 不接 | — | 过流报警输出，预留 |
| 电机电源 | 模块 B+/B- | — | 接电池，不走排针 |

**引脚占用红线**（选脚前必查）：
- PD11 = 蜂鸣器；PC6~PC9 = TIM8 电机 PWM；PB10/PB11 = UART3；PC10/PC11 = UART4 蓝牙；PA13/PA14 = SWD；PC13/14/15 = 备份域（弱驱动、无 TIM）
- PD8/PD9 是 UART3 的备用复用脚，但 UART3 实走 PB10/PB11，故空闲可用；两者无 TIM 复用，只做 GPIO
- 备用调速口：PB4 = TIM3_CH1（需 `GPIO_Remap_SWJ_JTAGDisable` 释放，不影响 SWD）

### 3.2 控制逻辑（GPIO 电平，无 PWM 无调速）

| PD8(RPWM) | PD9(LPWM) | 动作 |
|---|---|---|
| 高 | 低 | 升 |
| 低 | 高 | 降 |
| 高 | 高 | **动态刹车（停驻默认态）** |
| 低 | 低 | 滑行 |

规则：**平台停驻、失联、低压、坏帧一律双高刹车**，不滑行；上电 GPIO 复位默认低 + 初始化即刹车。方向反了改 `bts7960.h` 的 `LIFT_UP_MASK()/LIFT_DOWN_MASK()` 宏，不重接线。

## 4. 控制协议（蓝牙与 ROS 共用同一帧）

11 字节二进制帧（大端，XOR 校验）：

```
[0]=0x7B [1]=00 速度 / 10 释放 [2]=00
[3-4]=vx mm/s (±700) [5-6]=vy 升降 [7-8]=wz mrad/s (±1000)
[9]=字节0~8异或 [10]=0x7D
```

- **vy 复用为升降指令**：0=保持（刹车），+400=升，-400=降，|vy|≤1000
- **控制权仲裁**：只有"零速度帧"能申请控制权（要求 vy 也为 0）；持有方持续发帧保活（≤500ms 间隔）；释放帧或超时后归零，另一方须重新用零帧申请。ROS/蓝牙互不叠加、不抢占
- 任何失联/坏帧/物理失能 → 车轮 PWM 清零 + 升降刹车，恢复后必须重新零帧申请
- 回传：22 字节状态帧（5A…A5）+ 6 字节控制权帧（5B…A6），网页据此显示 owner/电压/轮速

## 5. 固件数据流（升降链路）

```
蓝牙(UART4 ISR) ─┐
                 ├→ 环形缓冲 → 0x7B 帧解析/校验 → 控制权仲裁 → ChassisControl_Step()
ROS(USART3 ISR) ─┘                                    │
                        100Hz Balance_task: lift(vy) → LiftMotor_Set(升/降/刹车)
                                        vx/wz → Drive_Motor → Set_Pwm(TIM8 PWM+DIR)
```

- 升降完全跟随控制权持有方；未授权时每周期强制 `LiftMotor_Brake()`
- 初始化顺序：`Balance_task` 启动时 `ChassisUart_Reset()` → `LiftMotor_Init()`（即刹车态）


**调试门控**（`chassis_config.h`，互斥，`#error` 保护）：`CHASSIS_PC8_PIN_TEST` / `CHASSIS_MOTOR_A(B)_PROBE` / `CHASSIS_CLOSED_LOOP_TEST` / `CHASSIS_OPEN_LOOP_TEST` / 正常 `CHASSIS_SERIAL_CONTROL`。加新外设时要保持这些宏互斥体系不破坏。

**实机验证顺序**：先杜邦线验证（74HC244@5V 下 3.3V 输入是边缘电平）→ 单电机点动验方向 → 平台满程往返 → 蓝牙失联刹车测试。

## 8. 已知坑（改动前必读）

1. **编码**：`.c/.h/.uvprojx` 多为 **GBK/GB18030**，严禁用会整文件重编码的工具编辑（中文注释会变乱码）；改法：git 恢复后用字节级替换（latin-1 读入、按实际 CRLF/LF 匹配锚点、latin-1 写回）。`docs/*.md`、`tools/*.html` 是 UTF-8，随意。
2. **引脚冲突**：见 3.1 红线清单；PD11 特别容易踩（蜂鸣器）。
3. **PWM/GPIO 区分**：底盘车轮 = TIM8 PWM + DIR 引脚（`motor.h`）；升降平台 = 纯 GPIO 电平。两套路径独立，别混用 `Set_Pwm`。
4. **测试盲区**：`test_chassis_profile.py` 读的是 C 源码文本，静态图/编译都不能替代实机时序验证；蓝牙距离与停止延迟需现场实测。
5. `CHASSIS_TRACK_WIDTH_M = 0.55`（实测轮距 550mm）；配置输出门控（`CHASSIS_CONFIG_CONFIRMED` 等）在接线/编码器未确认前不要打开。
