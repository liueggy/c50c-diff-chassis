# Chassis 串口速度指令（UART 差分控制）

适用：`Diff_Car` 目标（`CHASSIS_ENABLED=1`）。模块实现见 `BALANCE/chassis_uart_control.c`、`BALANCE/Inc/chassis_uart_control.h`，主机测试见 `tests/test_chassis_uart_control.py`。

## 目标与定位

在 Chassis 两轮差速底盘上，为 USART1 与 USART3 的运动指令提供一条**加固的解析路径**：缓冲接收、起始零指令解锁、指令超时、范围校验、帧同步与错误恢复，解析结果经差速逆运动学驱动机器人。模块与硬件解耦（只依赖 `stdint.h`），解析逻辑可在 PC 上直接测试。

## 帧格式

11 字节，与底盘既有串口协议一致：

| 字节 | 含义 |
|---|---|
| 0 | 帧头 `0x7B` |
| 1 | 控制模式，必须为 `0`（本模块只接受普通运动帧） |
| 2 | 保留，必须为 `0` |
| 3-4 | X 轴速度，有符号 16 位大端，单位 mm/s |
| 5-6 | Y 轴速度，有符号 16 位大端，**必须为 0** |
| 7-8 | Z 轴角速度，有符号 16 位大端，单位 mrad/s |
| 9 | 校验：前 9 字节逐字节异或（`Check_BCC`，同原协议） |
| 10 | 帧尾 `0x7D` |

解析后的单位：`vx` m/s、`wz` rad/s（模块内完成 mm/s→m/s、mrad/s→rad/s 换算）。

## 安全语义

- **起始零指令解锁**：上电或复位后，必须先收到一帧 `vx=0、wz=0` 的合法帧才会进入 `ACTIVE`，期间非零指令被忽略。避免噪声/半帧立即驱动电机。
- **范围限制**：`|vx| ≤ 700 mm/s`、`|wz| ≤ 1000 mrad/s`、`vy==0`、`byte1==byte2==0`；越界即判 `RX_ERROR` 并解除武装。
- **超时**：字节间超过 50 ms 丢半帧；持续 500 ms 无有效指令解除武装（输出归零）。
- **物理门控**：`ChassisUart_Step` 的 `physical_allowed` 传入 `CHASSIS_READY()`。未满足（含 `CHASSIS_CONFIG_CONFIRMED=0`）时清空接收缓冲、解除武装，状态为 `PHYSICAL_DISABLED`，电机仍由 `Set_Pwm` 的配置门控禁止输出。
- **错误恢复**：校验/帧尾/字段错误触发重同步（在窗口内重新寻找 `0x7B`）；硬件错误（ORE/NE/FE/PE）或环形缓冲溢出置 `RX_ERROR`，需重新零指令解锁。

## 状态（`ChassisUart_Status()`）

| 值 | 宏 | 含义 |
|---|---|---|
| 0 | `CHASSIS_UART_STATUS_WAIT_ZERO` | 等待起始零指令解锁 |
| 1 | `CHASSIS_UART_STATUS_ACTIVE` | 已解锁，正常输出速度 |
| 2 | `CHASSIS_UART_STATUS_TIMEOUT` | 指令超时 |
| 3 | `CHASSIS_UART_STATUS_PHYSICAL_DISABLED` | 物理/配置门控未满足 |
| 4 | `CHASSIS_UART_STATUS_RX_ERROR` | 校验/字段/溢出/硬件错误 |

OLED 首页（Chassis 正常目标）在 `CHASSIS PWM 2WD` / `CFG REQUIRED` 右侧显示 3 字符标签：`RUN` / `TO ` / `PD ` / `ERR` / `W0 `。

## 集成位置

| 文件 | 改动 |
|---|---|
| `BALANCE/chassis_uart_control.c` / `Inc/chassis_uart_control.h` | 解析模块本体 |
| `BALANCE/uartx_callback.c` | USART1/USART3 中断：Chassis 下改为 `ChassisUart_PushByte(byte, getSysTickCnt())`，并检测 ORE/NE/FE/PE 调 `ChassisUart_RxError()` |
| `BALANCE/balance_task.c` | 任务启动 `ChassisUart_Reset()`；正常路径每 10 ms 调 `ChassisUart_Step(getSysTickCnt(), CHASSIS_READY(), &vx, &wz)`，写入 `robot_control.Vx/Vz`（未运行则清零） |
| `BALANCE/show_task.c` | OLED 首页串口状态标签 |
| `USER/WHEELTEC.uvprojx` | 各目标 Balance 组加入 `chassis_uart_control.c` |

时间基为毫秒（`configTICK_RATE_HZ=1000`，`getSysTickCnt()` 即毫秒计数），与模块 `*_MS` 超时一致。

## 与原协议的差异（行为变更）

Chassis 目标下，USART1/USART3 的**运动指令不再经旧的 `UartxControll_Callback`**；旧回调及其仅被它使用的 `XYZ_Target_Speed_transition` 在 Chassis 下条件编译掉（`#if !CHASSIS_ENABLED`），避免未引用告警。因此 Chassis 串口下：

- 运动帧（`byte1==0`）由新解析器处理；
- 回充帧（`byte1==1/2`）、对接帧（`byte1==3`）、IP 帧（`byte1==0xFF`）**不再解析**（新解析器只接受 `byte1==0`）。

非 Chassis 目标（`CHASSIS_ENABLED=0`）完全保留原行为，不受影响。CAN 运动控制路径未改动。

**未做**：本次未烧录硬件。`CHASSIS_CONFIG_CONFIRMED` 已置 1，串口指令可驱动电机；但串口收发、零指令解锁、超时停车、越界拒绝仍需实车核对。普通构建的低压门控要求电池 ≥20 V（`Turn_Off`），12 V 台架供电不会输出。
