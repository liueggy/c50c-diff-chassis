# 串口协议与控制说明（Chassis 两轮差速底盘）

适用：`Diff_Car` 目标（`CHASSIS_ENABLED=1`）。命令解析模块见 `BALANCE/chassis_uart_control.c`、`BALANCE/Inc/chassis_uart_control.h`；回执帧见 `BALANCE/data_task.c`。主机测试：`tests/test_chassis_uart_control.py`。

串口：**USART1 与 USART3，115200 8N1**。板载 CH9102 USB 串口即二者之一（Windows 下常见 `COMx`）。

---

## 一、主机 → 底盘：命令帧（11 字节）

| 字节 | 含义 |
|---|---|
| 0 | 帧头 `0x7B` |
| 1 | 控制模式，必须为 `0` |
| 2 | 保留，必须为 `0` |
| 3-4 | X 轴速度，有符号 16 位**大端**，单位 mm/s |
| 5-6 | Y 轴速度，有符号 16 位大端，**必须为 0**（两轮差速无侧移） |
| 7-8 | Z 轴角速度，有符号 16 位大端，单位 mrad/s |
| 9 | 校验：前 9 字节逐字节异或 |
| 10 | 帧尾 `0x7D` |

解析后：`vx` m/s、`wz` rad/s（模块内完成 mm/s→m/s、mrad/s→rad/s）。差速逆解：左轮 = vx − wz·轮距/2，右轮 = vx + wz·轮距/2（A 左、B 右）。

| 指令 | 效果 |
|---|---|
| `vx=200, wz=0` | 直行前进 200 mm/s |
| `vx=-200, wz=0` | 后退 |
| `vx=0, wz=+500` | 原地左转（逆时针） |
| `vx=0, wz=-500` | 原地右转（顺时针） |
| `vx=200, wz=+300` | 前进中左转 |

示例帧：前进 200 = `7B 00 00 00 C8 00 00 00 00 B3 7D`；零帧 = `7B 00 00 00 00 00 00 00 00 7B 7D`。

## 二、底盘 → 主机：回执帧（22 字节，20 Hz）

| 字节 | 含义 |
|---|---|
| 0 | 帧头 `0x5A` |
| 1 | 状态字（见下） |
| 2-3 | 左轮**实测**速度 mm/s（s16 大端） |
| 4-5 | 右轮**实测**速度 mm/s（s16 大端） |
| 6-7 | 电压 mV（u16 大端） |
| 8-9 / 10-11 / 12-13 | 加速度 X / Y / Z（s16，ROS 轴） |
| 14-15 / 16-17 / 18-19 | 角速度 X / Y / Z（s16，ROS 轴） |
| 20 | 校验：前 20 字节逐字节异或 |
| 21 | 帧尾 `0xA5` |

- IMU 轴映射沿用原厂 ROS 习惯：`accel=(y, −x, z)`、`gyro=(y, −x, z)`；`FlagStop` 时角速度 Z 置 0。
- 回执在底盘构建下**替代**了原厂 24 字节 IMU 帧用于串口；CAN 仍发原厂帧。

**状态字位定义**

| bit | 含义 |
|---|---|
| 0 | 运行（串口已解锁并输出） |
| 1 | 串口超时（>500 ms 无有效指令） |
| 2 | 接收错误（校验/字段/溢出/硬件） |
| 3 | 串口待解锁 / 物理门控未就绪 |
| 4 | 停机（`FlagStop`） |
| 5 | 电机使能（EN） |
| 6 | 低压 |
| 7 | 自检错误 |

## 三、时序与安全

- **起始零指令解锁**：必须先收到一帧 `vx=0、wz=0` 的合法帧才进入 `ACTIVE`，期间非零指令被忽略。
- **连续发送**：指令间隔须 **< 500 ms**，否则超时停车（需重新零帧解锁）。
- **上电等待**：上电后约 **10 s** 内忽略串口（`CONTROL_DELAY`）。
- **范围**：`|vx| ≤ 700 mm/s`、`|wz| ≤ 1000 mrad/s`、`vy==0`、`byte1==byte2==0`；越界整帧判 `RX_ERROR` 并解除武装。
- **电压**：≥ 9.5 V（`CHASSIS_STOP_VOLTAGE_V`）；低于则停机。
- **错误恢复**：帧同步错误在窗口内重新寻找 `0x7B`；硬件错误或环形缓冲溢出置 `RX_ERROR`。

## 四、解析器状态（`ChassisUart_Status()`）

| 值 | 宏 | 含义 |
|---|---|---|
| 0 | `WAIT_ZERO` | 等待起始零指令解锁 |
| 1 | `ACTIVE` | 已解锁，正常输出 |
| 2 | `TIMEOUT` | 指令超时 |
| 3 | `PHYSICAL_DISABLED` | 物理/配置门控未满足 |
| 4 | `RX_ERROR` | 校验/字段/溢出/硬件错误 |

## 五、集成位置

| 文件 | 改动 |
|---|---|
| `BALANCE/chassis_uart_control.c` / `Inc/…h` | 命令解析模块本体 |
| `BALANCE/uartx_callback.c` | USART1/USART3 中断：Chassis 下改 `ChassisUart_PushByte(byte, getSysTickCnt())`，并检测 ORE/NE/FE/PE 调 `ChassisUart_RxError()` |
| `BALANCE/balance_task.c` | 启动 `ChassisUart_Reset()`；每 10 ms 调 `ChassisUart_Step(getSysTickCnt(), CHASSIS_READY(), &vx, &wz)` 写入 `robot_control.Vx/Vz` |
| `BALANCE/data_task.c` | 组织并发送 22 字节回执帧（`chassis_telem`） |
| `BALANCE/show_task.c` | 中文两页界面显示串口/状态 |
| `USER/WHEELTEC.uvprojx` | 各目标 Balance 组加入 `chassis_uart_control.c` |

时间基为毫秒（`configTICK_RATE_HZ=1000`）。

## 六、与原协议的差异

Chassis 目标下，USART1/USART3 的运动指令**不再经旧的 `UartxControll_Callback`**（旧回调及其仅用的 `XYZ_Target_Speed_transition` 被条件编译掉）。因此 Chassis 串口下只解析 `byte1==0` 的运动帧；**回充（1/2）、对接（3）、IP（0xFF）帧不再解析**。非 Chassis 目标完全保留原行为。**本协议不同于原厂 WHEELTEC ROS 协议**，ROS 侧需按本文档自行收发。

## 七、ROS 侧对接

- 订阅 `/cmd_vel`（`geometry_msgs/Twist`）→ 打包命令帧；**定时器 20 Hz 持续发送**并以 <500 ms 看门狗，启动先发零帧。
  - `vx = linear.x * 1000`（mm/s，s16）；`wz = angular.z * 1000`（mrad/s，s16）。
- 解析回执帧：
  - 左右轮实测 → `sensor_msgs/JointState`（轮关节），或差速正解算得 `(vx,wz)` 喂 `nav_msgs/Odometry`；
  - 加速度/角速度 → `sensor_msgs/Imu`；电压 → `sensor_msgs/BatteryState`；状态字 → 诊断。
- 接线：C50C 的 **USART1 或 USART3**，**3.3 V TTL**；经板载 CH9102 时勿拉 DTR/RTS（防复位）。
