# 串口协议与控制说明（接口行为v1.2）

适用：`Diff_Car` 目标（`CHASSIS_ENABLED=1`）。命令解析模块见 `BALANCE/chassis_uart_control.c`、`BALANCE/Inc/chassis_uart_control.h`；回执帧见 `BALANCE/data_task.c`。主机测试：`tests/test_chassis_uart_control.py`。

有线ROS运动端口：**USART3，115200、8N1、无硬件流控**；JDY-33无线控制使用独立UART4（默认9600）。两路采用控制权仲裁，详见[蓝牙与客户端开发](蓝牙控制与客户端开发.md)。TX=PB10、RX=PB11；3.3 V TTL，TX/RX交叉并共地。USB转TTL转换器和Linux设备名由上位机负责人确认。不能仅凭板载USB或COM号认定已经接到USART3。

USART1保留串口下载和状态回传，Chassis构建下收到的USART1数据不会进入运动解析器。其他原厂车型保持原行为。

本仓库交付固件、协议和参考工具；ROS 2节点由上位机负责人在其仓库实现。v1.2保持速度帧11字节与遥测22字节布局，新增mode=0x10释放指令和独立6字节控制权回报。11/22字节帧无版本或序号。

## 一、主机 → 底盘：命令帧（11 字节）

| 字节 | 含义 |
|---|---|
| 0 | 帧头 `0x7B` |
| 1 | `0`速度指令；`0x10`释放本通道控制权（速度字段须全零） |
| 2 | 保留，必须为 `0` |
| 3-4 | X 轴速度，有符号 16 位**大端**，单位 mm/s |
| 5-6 | Y 轴速度，有符号 16 位大端，**必须为 0**（两轮差速无侧移） |
| 7-8 | Z 轴角速度，有符号 16 位大端，单位 mrad/s |
| 9 | 校验：前 9 字节逐字节异或 |
| 10 | 帧尾 `0x7D` |

解析后：`vx` m/s、`wz` rad/s（模块内完成 mm/s→m/s、mrad/s→rad/s）。差速逆解：左轮 = vx − wz·轮距/2，右轮 = vx + wz·轮距/2（A 左、B 右）。

| 指令 | 效果 |
|---|---|
| `vx=200, wz=0` | 直行前进 200 mm/s |
| `vx=-200, wz=0` | 后退 |
| `vx=0, wz=+500` | 原地左转（逆时针） |
| `vx=0, wz=-500` | 原地右转（顺时针） |
| `vx=200, wz=+300` | 前进中左转 |

示例帧：前进 200 = `7B 00 00 00 C8 00 00 00 00 B3 7D`；零帧 = `7B 00 00 00 00 00 00 00 00 7B 7D`。

## 二、底盘 → 主机：回执帧（22 字节，20 Hz）

| 字节 | 含义 |
|---|---|
| 0 | 帧头 `0x5A` |
| 1 | 状态字（见下） |
| 2-3 | 左轮**实测**速度 mm/s（s16 大端） |
| 4-5 | 右轮**实测**速度 mm/s（s16 大端） |
| 6-7 | 电压 mV（u16 大端） |
| 8-9 / 10-11 / 12-13 | 加速度 X / Y / Z（s16，ROS 轴） |
| 14-15 / 16-17 / 18-19 | 角速度 X / Y / Z（s16，ROS 轴） |
| 20 | 校验：前 20 字节逐字节异或 |
| 21 | 帧尾 `0xA5` |

- IMU轴映射：`accel=(y, −x, z)`、`gyro=(y, −x, z)`，对应驱动中的传感器轴变换，安装朝向仍需联调核对。
- 当前ICM20948配置：加速度±2g，16384 LSB/g；陀螺仪±500°/s，65.5 LSB/(°/s)。换算：`a = raw / 16384 × 9.80665` m/s²；`ω = raw / 65.5 × π / 180` rad/s。量程来自 `HARDWARE/ICM20948/ICM20948.c`，比例见[ICM20948手册](manuals/chips/ICM20948_数据手册.pdf)第11～12页。
- 回传为驱动处理后的整数计数，不是已换算的SI数值。开机约10秒后陀螺仪扣除初始化零偏；加速度扣除初始化偏置，并在Z轴保留16384计数的重力基准。启动期间应保持静止；这不等同于经过完整姿态/重力补偿的线加速度。
- 陀螺仪Z轴始终回传传感器值，电机停机时也不会强制清零。停机期间仍可能有人推动或转动车体。
- 回执在底盘构建下**替代**了原厂 24 字节 IMU 帧用于串口；CAN 仍发原厂帧。

**状态字位定义**

| bit | 含义 |
|---|---|
| 0 | ARMED：串口已解锁，指令仍在有效期内；不表示电机正在输出 |
| 1 | 串口超时（>500 ms 无有效指令） |
| 2 | 接收错误（校验/字段/溢出/硬件） |
| 3 | 串口待解锁 / 物理门控未就绪 |
| 4 | OUTPUT_STOPPED：电机输出被禁止/清零（`FlagStop`）；不保证车轮已机械静止 |
| 5 | 电机使能（EN） |
| 6 | 低压 |
| 7 | 自检错误 |

## 三、时序与安全

- **起始零指令解锁**：无人控制时由零帧申请控制；UART3与蓝牙只能一方生效，非控制方数据不影响当前运动。必须检查6字节回报中的owner；详见蓝牙文档。
- **连续发送**：指令间隔须 **< 500 ms**，否则超时停车（需重新零帧解锁）。
- **上电等待**：前约10秒忽略接收，控制就绪前约12.3秒丢弃排队数据；就绪后须收到新的零帧。
- **失能恢复**：配置、使能EN、9.5～28 V检测电压、软件停机、错误标志、硬件版本和启动等待都纳入解析器门控。失能期间丢弃帧；恢复后的第一周期清空队列，必须再收到零帧，不能重放旧非零指令。
- **异常停车**：超时、坏帧、越界、失能等导致禁止状态时，当次100 Hz控制周期清零PWM、目标/平滑速度和PI，不经过普通速度平滑。500ms是命令失效阈值；正常调度下额外检测延迟小于约10ms。物理低压依赖10 Hz电压采样/滤波，因此不能宣称从电压下降开始10ms内必然停机。
- **零速度**：合法零帧当周期清零输出与PI，但保持ARMED，可随后接收新运动帧。普通非零速度变化仍使用原平滑控制。
- **停止边界**：PWM清零是电气停止指令，实际车轮受惯性、负载与驱动器制动影响；串口指令不是硬件急停，也不保证固定制动距离。
- **范围**：`|vx| ≤ 700 mm/s`、`|wz| ≤ 1000 mrad/s`、`vy==0`、速度帧`byte1==byte2==0`；释放帧`byte1==0x10`且其他载荷全零；越界整帧判 `RX_ERROR` 并解除武装。
- **电压**：检测值在9.5～28 V范围才允许串口运动；无效数值也禁止。9.5 V按当前固定12 V供电设置，不作为未知电池化学体系的放电保护建议。
- **错误恢复**：帧同步错误在窗口内重新寻找 `0x7B`；硬件错误或环形缓冲溢出置 `RX_ERROR`。

## 四、解析器状态（`ChassisUart_Status()`）

| 值 | 宏 | 含义 |
|---|---|---|
| 0 | `WAIT_ZERO` | 等待起始零指令解锁 |
| 1 | `ACTIVE` | 已解锁，正常输出 |
| 2 | `TIMEOUT` | 指令超时 |
| 3 | `PHYSICAL_DISABLED` | 物理/配置门控未满足 |
| 4 | `RX_ERROR` | 校验/字段/溢出/硬件错误 |

## 六、与原协议的差异

Chassis目标下，USART3的运动指令**不再经旧的 `UartxControll_Callback`**（旧回调及其仅用的 `XYZ_Target_Speed_transition` 被条件编译掉）。因此 Chassis串口只解析速度与释放控制帧；**回充（1/2）、对接（3）、IP（0xFF）帧不再解析**。非 Chassis 目标完全保留原行为。**本协议不同于原厂 WHEELTEC ROS 协议**，ROS 侧需按本文档自行收发。

## 七、ROS 侧对接

本仓库不实现ROS 2节点。上位机负责人负责：

- 订阅 `/cmd_vel`（`geometry_msgs/msg/Twist`，若项目采用TwistStamped由对方提取twist）→ 打包命令帧；建议20 Hz发送，启动/重连先持续零帧至收到ARMED状态。
- 上游 `/cmd_vel` 也必须有超时，例如300ms无新消息转零；不能持续重发旧非零速度来绕过板端500ms超时。
- 通信错误、失能恢复后丢弃旧速度，先零帧重解锁，等待新的上游运动指令。
- 正方向：ROS机体X向前、Z向上，`linear.x>0`前进、`angular.z>0`左转。其余Twist分量应为0；单位转换和坐标系由双方按联调记录确认。
  - `vx = linear.x * 1000`（mm/s，s16）；`wz = angular.z * 1000`（mrad/s，s16）。
- 解析回执帧：
  - 左右轮实测由mm/s除1000得到m/s；`vx=(vL+vR)/2`、`wz=(vR−vL)/0.55`。若发布轮关节速度，需要再除有效轮半径转成rad/s；Odometry积分、时间戳和TF由上位机实现。
  - 加速度/角速度按第二节转换后才发布`sensor_msgs/msg/Imu`；没有姿态四元数，orientation应明确标记不可用，不可伪造。电压除1000为V，不能只凭电压声称电量百分比。状态字按ARMED与OUTPUT_STOPPED分别解释。
- 接线：运动仅使用 **USART3** 的3.3 V TTL；下载使用USART1。参考工具打开转换器前设DTR/RTS为false，仍需按转换器/板载电路核对实际复位行为。

## 十、接口交接与实车验收

协议帧是周期广播状态，不是每条命令的逐帧ACK；无序号和板端时间戳，ROS侧不能声称逐条命令确认或精准采样时刻。v1.2保持原两类帧长度，追加独立控制权帧；接收方须按流忽略或解析该新帧，未来其他字段仍需约定新版本。

交接对象为上位机负责人，ROS节点在其仓库实现。本仓库负责UART3固件、本文字段/单位/状态与参考帧、硬件接线说明和板端测试。

架空驱动轮依次验收并记录：

1. 未发零帧时非零命令不启动；零帧后前进/后退/左右转方向及反馈正确。
2. 串口1发送运动帧无动作；串口3正常收发，不能跨端口拼成有效帧。
3. 运行时拔串口，最后有效帧后约500～510ms清除电机输出；反馈归零时间按实测记录。
4. 坏校验、越界、横向速度非零均停机；恢复合法非零帧仍不启动，必须先零帧。
5. 使能OFF停机，OFF期间持续非零发令；ON后保持停止，重新零帧解锁再发新运动帧才运行。
6. 零帧停止时确认ARMED与OUTPUT_STOPPED可同时置位；手动车体转动时gyro Z仍有真实反馈。
7. 网页松开/切后台/关闭/模拟失联均停车；恢复后需重新操作，旧速度不复用。

v1.2会在每个22字节遥测后追加6字节控制权帧：`5B 01 owner state XOR A6`，owner为0/3/4（无人/UART3/蓝牙）；XOR覆盖前4字节。自研ROS接收器须按帧头和长度处理混合流，确认owner=3后再发运动。

当前这些新增安全行为已由源码和主机测试验证；实车测时、制动距离以及ROS端适配结果由双方联调补充。

补充测试：`python tests/test_bluetooth_control.py`、`python tests/test_bluetooth_tx.py`。旧蓝牙APP协议已在Chassis构建下关闭，不可再用字母或旧调参包控制本车。

## 首页连接显示

首页保留运行状态、电压，并显示“蓝牙已开启”和“串口 在线 / 未连接”。“蓝牙已开启”表示本固件启用了蓝牙控制功能，不代表手机已经配对连接，也不保证模块供电、波特率和硬件正常。

串口项只观察 USART3 收到的有效零速度或速度指令；仅插线、打开串口窗口或接收板子遥测不会变为在线。最近 1 秒内有有效指令则显示在线，否则显示未连接。显示随原有 10 Hz 屏幕任务刷新，不新增查询或应答协议。蓝牙占用控制权或使能关闭时，USART3 的有效通信仍可独立显示在线，在线不表示已取得控制权或允许运动。非法帧、释放帧不刷新此显示。

显示的 1 秒宽限期只用于减少界面跳变；运动控制的 500 毫秒超时停车、零帧解锁和控制权互斥规则保持不变。
